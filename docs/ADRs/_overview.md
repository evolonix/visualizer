# Architecture Decision Records

Software engineering teams need to document research, reasoning, and decisions related to choices of technology and architectures. "Architecture Decisions Records" (aka ADRs) become document the functional or non-functional requirements and decisions that are architecturally significant.

> Within FE-Nx, ADRs are colocated within the repository as `*.md` files; instead of external documentation managed in an remote Confluence or wiki system.

The following ADRs are currently available:

- [Frontend Nx Mono-Repositories](./fe-nx-repos.md)
- [CodeOwners and Remote API interfaces](./remote-api-interfaces.md)
- [Reactive Stores](./reactive-stores.md)
- [Tailwind within Design-Development](./tailwind-css.md)
- [Leverage the NextJS Platform](./using-nextjs.md)
- [Versioned REST URLs](./versioned-rest.md)
