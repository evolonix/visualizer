# Semantic Releases

When a GitHub Release is created for a previously tagged artifact, versions are automatically generated by the [release](https://nx.dev/features/manage-releases) command provided by Nx using semantic versioning to bump your project's version, create the changelog, and update the Release description.

Under the hood, it uses project graph from Nx to analyze commits for every configured project and filters out the commits that don't affect a given project or it's dependencies.

## How it works

1. **Analyze commits**: Nx analyzes commits since the last release to determine the type of release (major, minor, patch)
2. **Generate version**: Based on the commits, Nx generates a new version for the project and updates the package.json file's version field (however, without commiting the change)
3. **Update changelog**: Nx generates a changelog with the new version and the changes since the last release
4. **Update GitHub Release description**: Nx updates the Release description with the generated changelog

### Versioning

- Major versions are bumped when a commit includes a breaking change
- Minor versions are bumped when a commit includes a new feature
- Patch versions are bumped when a commit includes a bug fix
